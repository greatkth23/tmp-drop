# 업로드 작업/내역 분리 — 2026-10-04

## 문제와 피드백

사용자 스크린샷에서 완료 파일이 새 대기 파일보다 먼저 표시되고, 파일 정보/상태/보관 기간/버튼이 두세 줄로 분산되어 있었다. UX 및 문구 자문을 반영해 상태 분류와 도구 배치를 먼저 수정했다.

## 변경

- 기본 화면은 현재 업로드. 대기·진행·실패·인증 필요·결과/취소 확인 항목을 유지한다.
- READY/CANCELLED만 전송 내역에 분리하고, 최신 추가 항목부터 표시한다. 완료 시 사용자가 보고 있는 영역을 자동 전환하지 않는다. 새 파일을 추가하면 현재 업로드로 돌아온다.
- 전송 내역은 기존 메모리 기반 동작과 같은 현재 탭 범위이며 새로고침하면 초기화된다. 범위를 UI에 표시한다. 내역에서 제거/내역 비우기는 서버 파일을 삭제하지 않는다. 비우기는 확인 대화상자를 거친다.
- 파일 추가·새 파일 보관·대상 수/용량·업로드 시작을 흰 상단 고정 도구 모음 하나로 통합했다. 기존의 별도 회색 추가 박스와 시작 바를 제거했다.
- 업로드 행은 데스크톱에서 파일/상태/보관·만료/동작을 같은 줄에 배치한다. 진행률과 오류는 필요한 경우에만 아래에 표시한다. 모바일은 읽기 순서에 맞게 줄바꿈한다.
- 새 파일 기본 보관은 6시간(21600초). 기존 개별 설정을 덮어쓰지 않는다. 단축어 안내와 unsigned 생성기 기본값도 맞췄다. 이미 설치된 단축어는 retentionSeconds를 직접 변경해야 한다.
- 선택 ZIP 다운로드/선택 삭제/새로고침을 같은 도구 모음에 둔다. 선택 개수와 전체 선택은 목록 바로 위에 유지한다.
- 한도 초과 시 완료 내역이 없는 경우에는 파일 수를 줄이라고 안내한다. 내역이 있으면 내역 비우기도 안내한다.

## 검증

- npm run check: 타입 검사, Prettier, 73개 테스트, production build 통과.
- 엔진 검사: 내역 비우기 후 대기 파일과 개별 보관 설정 유지, 서버 변경 요청 없음. 실패/오프라인/재인증/확정 중 항목은 내역으로 분류하지 않는다.
- 실제 UploadPage 서버 렌더 검사: 완료 파일을 현재 목록에서 제외하고 대기/실패 파일 및 복구 버튼 유지. 새 파일 선택기는 6시간이고 기존 개별 24시간 값은 유지. 업로드 시작 버튼은 파일 행보다 앞에 위치.
- 운영 UI: 새 파일 보관 6시간, 현재/내역 전환, 안내와 상단 도구 모음 확인. 320/390px에서 업로드 화면 가로 넘침 없음.
- 검수 파일의 운영 업로드는 브라우저 권한 거절로 수행하지 않았다. 다른 경로로 우회 업로드하지 않았다. 따라서 이번 변경의 실제 업로드 완료→내역 이동 및 파일이 있는 상태의 최종 시각 검수는 미완료이며 자동검사 결과와 구분한다.
