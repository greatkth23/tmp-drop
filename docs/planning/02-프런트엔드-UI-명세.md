# Personal Temporary Drop — 프런트엔드 UI·UX 상세 명세

작성일: 2026-10-02 · 상세 구현 계획의 UI 부속 명세 · 기본 언어: 한국어

## 1. 디자인 방향

서비스 이름은 화면에서 **Temporary Drop**, 작은 보조 문구로 **PERSONAL FILE TRANSFER**를 사용한다. 전달·전송·만료 상태가 가장 먼저 읽히는 작업 도구로 설계한다. 마케팅용 큰 히어로, 사진, 장식용 그래프는 넣지 않는다.

화면은 따뜻한 밝은 회색 배경, 흰 작업 패널, 짙은 남색 본문, 깊은 청록색 주요 버튼으로 구성한다. 색은 브랜드 장식보다 ‘가능·진행·주의·실패’를 구별하는 데 사용한다. 상태는 색만으로 전달하지 않고 아이콘·텍스트를 함께 쓴다.

원안의 ‘간단한 세 화면’을 유지하되 인증 상태에 따라 페이지 내부가 달라진다. 사용자가 백엔드 용어를 배울 필요는 없다. Capability, multipart, R2, D1은 제품 화면의 일반 안내에 표시하지 않는다.

## 2. 정보 구조

| URL | 표시 이름 | 주된 행동 | 접근 조건 |
|---|---|---|---|
| `/` | 파일 받기 | PIN 입력 또는 파일 다운로드 | PIN 이후 목록 |
| `/upload` | 파일 올리기 | TOTP 또는 파일 선택·전송 | temp/browser device |
| `/devices` | 내 기기 | 등록 기기 확인·단축어 토큰 발급·폐기 | browser device 또는 TOTP 관리 인증 |

전역 헤더는 로고·세 메뉴·현재 환경 표시로 구성한다. ‘파일 받기’ 인증과 ‘파일 올리기’ 인증은 서로 독립이다. 메뉴 이동이 업로드를 중단하지 않는다. 업로드 진행 중 다른 페이지에서는 헤더 또는 하단에 ‘2개 파일 전송 중 · 업로드로 이동’ 표시를 유지한다.

프로덕션에는 시안의 ‘상태 미리보기’ 선택기가 없다. HTML 시안은 디자인 검토용이므로 별도 상단 바에서 가상 상태를 선택한다.

### 서체·간격·형태

- 시스템 한글 sans-serif: `-apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans KR", "Malgun Gothic", sans-serif`. 외부 폰트 요청 없이 시작한다.
- 페이지 제목 desktop 32px/1.25/700, mobile 26px. 카드 제목 18px/1.4/650, 본문 15–16px/1.6, metadata 13px/1.5.
- PIN/TOTP·크기·남은 시간은 tabular-nums. 코드 입력 28px, 자간 0.25em. 의미 없는 전체 대문자 본문은 피한다.
- spacing scale: 4, 8, 12, 16, 24, 32, 48px. 섹션 32px, 패널 내부 24px, 모바일 20px.
- radius: 입력·버튼 10px, 패널 16px, badge 999px. 둥근 모양을 과도하게 중첩하지 않는다.
- 버튼 최소 높이 44px, 모바일 48px. 아이콘만 있는 버튼은 accessible name과 44×44px 터치 영역.
- 기본 border 1px, dialog에만 약한 그림자. 상태 변화 120–180ms, reduced-motion이면 전환 최소화.
- Lucide 같은 일관된 outline 아이콘 세트 선택 가능. 패키지·라이선스는 착수 시 고정. 시안은 텍스트 기호로 대체한다.

## 4. 반응형 레이아웃

| 폭 | 헤더 | 본문 | 전송 항목 |
|---|---|---|---|
| 320–599px | 로고 + 메뉴 가로 3개, 줄바꿈 허용 | 1열, 좌우 16px | 파일명→metadata→bar→버튼 |
| 600–959px | 로고·탭 한 줄 가능 | 1열 또는 보조 정보 하단 | 넓은 1행 카드 |
| 960px 이상 | 로고 좌·탭 중앙·상태 우 | max-width 1120px, 주영역+280px 보조영역 | 표·카드 모두 가능 |

업로드 화면은 desktop에서 왼쪽 작업 공간과 오른쪽 ‘현재 이용 방식·보관 안내’가 나뉜다. 모바일은 안내를 작업 아래로 내린다. 상태 배너는 우선순위가 높으므로 항상 작업 영역 위다. 다운로드 표는 좁은 화면에서 카드 목록으로 바뀌며 가로 스크롤을 기본 UX로 사용하지 않는다.

신뢰 여부·remaining time·전송 진행률을 모바일에서 숨기지 않는다. 긴 파일명은 2줄까지 표시하고 전체 이름은 펼치기/접근성 이름으로 확인한다. 확장자는 가능하면 남기고, tooltip만으로 전체 정보를 제공하지 않는다.

## 5. 공통 컴포넌트 계약

| 컴포넌트 | 주요 props | 상태 | 접근성·행동 |
|---|---|---|---|
| Button | variant, size, busy, disabled | default/hover/focus/loading | busy 중 중복 실행 방지, 이름 유지 |
| TextField | label, help, error | idle/invalid/disabled | label 연결, aria-describedby |
| CodeInput | length, autocomplete | empty/partial/valid/error | 실제 단일 input, 숫자 키패드·붙여넣기 |
| StatusBanner | tone, title, body, action | info/success/warning/error | 중요한 변경만 live region |
| SessionBadge | mode, expiresAt | trusted/temp/expired | 카운트다운 매초 음성 알림 금지 |
| FilePicker | multiple, limits | idle/drag/disabled | button+input, drop 없이도 사용 |
| RetentionSelector | value, options | selected/disabled | native select 또는 radio group |
| UploadItem | metadata, state, bytes | 전체 전송 상태 | progressbar aria-valuenow |
| DownloadItem | filename,size,expiry | idle/starting/error | 다운로드 결과를 과장하지 않음 |
| DeviceItem | kind,current,scope,lastUsed | active/revoked | 현재 기기 표시, 행 전체 클릭 금지 |
| Dialog | title, description, actions | open/busy/error | focus trap, Esc, 이전 focus 복귀 |

PIN/TOTP는 네 칸·여섯 칸 독립 input 대신 하나의 input을 권고한다. 시각적으로 분리해 보이게 할 수 있지만 복사·붙여넣기·VoiceOver·자동완성은 단일 필드로 동작해야 한다. `type=text`, `inputmode=numeric`, 길이 제한, 코드 붙여넣기 시 공백 제거. TOTP에는 `autocomplete=one-time-code`, PIN에는 별도 적절한 autocomplete 정책을 적용한다.

## 6. 다운로드 화면

### 6.1 잠금 상태

```text
Temporary Drop                      파일 받기  파일 올리기  내 기기

                         [작은 잠금 아이콘]
                          파일을 받아보세요
                   다운로드 PIN을 입력하면 목록을 볼 수 있어요.

                         다운로드 PIN
                         [ • • • • ]
                  □ 내 기기에서만 30일 동안 기억
                         [파일 목록 열기]

                    파일을 올리려면 ‘파일 올리기’를 선택하세요.
```

입력 완료만으로 자동 제출하지 않는다. Enter 또는 버튼으로 명시적으로 제출한다. PIN 값은 마스킹하되 접근 가능한 표시/숨기기 옵션은 선택 사항이다. 기억하기는 OFF. 오류는 ‘PIN을 다시 확인해 주세요.’, 제한은 ‘시도 횟수를 초과했습니다. 2분 후 다시 시도해 주세요.’로 표시한다. 초기 화면에서 파일 개수·이름·총 용량을 노출하지 않는다.

### 6.2 목록 상태

상단: ‘받을 수 있는 파일’ + ‘보관 시간이 끝나면 자동으로 사라집니다.’. 우측: 새로고침, 잠금. 파일 행: 종류 아이콘, 파일명, 크기, 업로드 완료 상대 시각, 만료까지 남은 시간, 다운로드 버튼.

| 필드 | 표시 예시 | 규칙 |
|---|---|---|
| 이름 | experiment-data.zip | 원문 안전 출력, 최대 2줄 |
| 크기 | 16.0 GiB | MiB/GiB 사용해 기술 크기와 일치 |
| 완료 시각 | 5분 전 | 세부 정보에서 절대 시각·시간대 제공 |
| 만료 | 23시간 남음 | 1시간 미만은 주의색, 만료 시 비활성·목록 갱신 |
| 행동 | 다운로드 | 준비 중에는 ‘연결 중…’, 완료됐다고 표시하지 않음 |

브라우저의 실제 다운로드 완료 여부를 페이지가 항상 알 수 없으므로 버튼 후 ‘다운로드를 시작했습니다.’ 이상을 주장하지 않는다. 실패하면 ‘다운로드 링크를 만들지 못했습니다. 다시 시도해 주세요.’. 목록은 다운로드 세션 만료 시 비우고 잠금 화면으로 전환한다.

### 6.3 빈·오류 상태

- 빈 목록: ‘아직 받을 파일이 없어요.’ / ‘다른 기기에서 파일을 올리면 여기에 표시됩니다.’
- 마지막 파일 만료: ‘보관 중인 파일이 모두 만료되었습니다.’
- 목록 조회 실패: 기존 목록을 마지막 확인 시각과 함께 유지하거나 최초 조회면 오류 패널, ‘다시 불러오기’.
- 페이지 로딩: 3행 정도 skeleton, 인증 확인 전 가짜 파일명을 렌더링하지 않음.
- 세션 종료: ‘이 브라우저의 다운로드 잠금을 설정했습니다.’

## 7. 업로드 화면

### 7.1 TOTP 인증

제목 ‘파일을 올리려면 인증해 주세요’. 도움말 ‘Google Authenticator의 6자리 코드를 입력하세요.’. 단일 6자리 input, 신뢰 체크 OFF, 조건부 기기명 입력, ‘인증하고 계속’ 버튼.

체크박스: **‘내 개인 기기입니다. 다음부터 인증 없이 업로드합니다.’**
체크하지 않은 기본 안내: **‘이 PC에서는 15분 동안 새 업로드를 시작할 수 있어요.’**
체크한 경우 안내: **‘공용 PC에서는 선택하지 마세요.’** + ‘기기 이름’(예: 집 Windows).

인증 성공은 체크 상태에 따라 temp 또는 trusted로 전환한다. code는 즉시 메모리에서 제거한다. 관리 목적 TOTP dialog와 업로드 목적을 문구로 구분한다. 실패·재사용·rate-limit을 같은 범용 ‘서버 오류’로 표시하지 않는다.

### 7.2 기본 작업 화면

```text
파일 올리기                              [신뢰하는 기기 · 집 Windows]
다른 기기에서 받을 파일을 잠시 보관하세요.

┌────────────────────────────────────┐  ┌──────────────────┐
│  ↑                                 │  │ 보관 안내        │
│  파일을 여기에 놓아주세요           │  │ 완료 후 24시간   │
│  또는 [파일 선택]                  │  │ 자동 삭제됩니다  │
│  파일당 최대 32 GiB                │  │                  │
│  기본 보관 기간 [24시간 ▾]         │  │ 전송 중에는      │
└────────────────────────────────────┘  │ 이 탭을 유지     │
                                       └──────────────────┘
전송 목록                       대기 1 · 전송 1 · 완료 2
┌────────────────────────────────────┐
│ experiment-video.zip       전송 중 │
│ 11.8 / 16.0 GiB · 48 MiB/s         │
│ ███████████████░░░░ 74%            │
│ 약 1분 30초 남음           [취소] │
└────────────────────────────────────┘
```

선택 후 즉시 전송보다 **선택 → 대기 목록 확인·보관기간 지정 → ‘업로드 시작’**을 기본으로 권고한다. 폴더·수십 파일의 실수 업로드를 줄이고 보관 정책을 명시할 수 있다. 전송 중 추가 파일을 선택하면 대기열에 추가하고 새 항목만 시작할 수 있다. 생성 권한은 실제 슬롯 배정 시 서버가 판단한다.

기본 보관 기간 변경은 이후 선택 파일에 적용한다. 기존 대기 파일은 각 항목에서 변경 가능. 서버 생성 후에는 수정 불가. UI 설명은 ‘업로드 완료부터 24시간 보관’처럼 기준 시점을 항상 포함한다.

### 7.3 업로드 상태별 표시

| 내부 UI 상태 | 화면 문구 | 진행률 | 행동 |
|---|---|---|---|
| queued | 대기 중 | 없음 | 보관 변경·목록에서 제거 |
| needs_auth | 인증 후 시작할 수 있어요 | 없음 | 다시 인증 |
| creating | 전송 준비 중 | indeterminate | 취소 |
| uploading | 전송 중 | percent + bytes | 취소 |
| retry_wait | 연결을 다시 시도하고 있어요 | 마지막 확정값 | 취소 |
| offline | 인터넷 연결을 기다리고 있어요 | 마지막 확정값 | 취소 |
| paused_error | 일부 데이터를 보내지 못했습니다 | 마지막 확정값 | 다시 시도·취소 |
| finalizing | 업로드를 확인하고 있어요 | 100%, 미완료 표시 | 결과 대기 |
| ready | 업로드 완료 | 완료 아이콘 | 목록에서 지우기·파일 받기로 이동 |
| cancel_pending | 취소를 확인하고 있어요 | 동결 | 결과 대기 |
| cancelled | 취소됨 | 없음 | 목록에서 지우기 |
| failed | 업로드할 수 없습니다 | 없음 | 이유에 맞는 새로 시작 |

‘목록에서 지우기’는 브라우저 전송 이력만 제거한다. 서버 파일 삭제와 혼동하지 않도록 ‘이 화면에서 지우기’로 표시해도 된다. 완료 100%와 READY를 구별한다. MIME 아이콘이나 파일 이름은 성공 근거가 아니다.

### 7.4 공용 PC 세션

정상: ‘공용 PC · 새 업로드 가능 시간 12:34’. 보조: ‘시간이 끝나도 진행 중인 파일은 계속 전송됩니다.’

2분 이하: amber로 바꾸고 ‘새 파일을 올릴 수 있는 시간이 얼마 남지 않았습니다.’. 경고를 매초 다시 announce하지 않는다.

만료: **‘새 업로드 가능 시간이 끝났습니다. 진행 중인 1개 파일은 계속 전송됩니다.’** + ‘다시 인증’. drop zone은 비활성. 이미 대기한 미생성 항목에는 ‘인증 필요’. 전송 카드·XHR·capability는 그대로 유지한다.

인증을 다시 해도 기존 업로드를 새로운 session에 자동 귀속시키지 않는다. 기존 capability는 원래 parent를 유지한다. 전송 UI는 두 세션의 파일을 함께 보여줄 수 있다.

### 7.5 중단과 종료

개별 취소 dialog: ‘이 파일의 업로드를 취소할까요?’ / ‘전송한 데이터는 정리됩니다. 다시 올리려면 처음부터 시작해야 합니다.’ / ‘계속 업로드’, ‘업로드 취소’.

공용 PC 종료: ‘이 PC에서 작업을 마칠까요?’ / ‘진행 중인 업로드 2개가 취소되고 업로드·다운로드 접근이 종료됩니다.’ / ‘계속 사용’, ‘취소하고 종료’. 활성 업로드가 없으면 간단한 확인 없이 종료 가능하다.

개인 기기에서는 ‘이 기기에서 로그아웃’과 ‘기기 신뢰 해제’를 같은 버튼처럼 취급하지 않는다. v1은 명확하게 **‘이 기기의 신뢰 해제’**를 제공하고 TOTP로 확인한다. 종료했다고 안내하면서 유효한 td를 남겨 바로 다시 로그인되는 동작을 만들지 않는다.

### 7.6 성능·시간 표기

- bytes는 성공한 part + 현재 전송 시도만 합산. retry에서 이전 시도 바이트 중복 제외.
- 속도는 최근 5–10초 이동 평균, 초기 3초는 ‘속도 계산 중’.
- ETA는 충분한 표본이 생긴 후 반올림. 불안정한 연결에서 초 단위 정확도를 가장하지 않는다.
- UI 업데이트 최대 초당 4–5회. aria-live는 10% 구간·상태 변화 중심.
- 남은 전송 허용 시간이 예상 소요시간보다 짧으면 ‘현재 속도에서는 제한 시간 안에 끝나지 않을 수 있습니다.’. 아직 구현되지 않은 자동 연장 버튼은 제공하지 않는다.

## 8. 내 기기 화면

### 8.1 목록

제목 ‘내 기기’. 설명 ‘등록한 기기는 인증 없이 파일을 올릴 수 있어요.’. 오른쪽 ‘iPhone 단축어 연결’.

각 행에는 기기 유형 아이콘, 이름, 현재 기기 badge, 범위(브라우저 업로드/단축어 업로드 전용), 마지막 사용 시각, ‘권한 해제’를 표시한다. 실제 기기 하드웨어를 식별한다고 표현하지 않는다. 브라우저 프로필별 credential 등록이며 같은 Windows PC에서 두 브라우저는 별도 기기로 보일 수 있다.

목록 인증이 없으면 ‘기기 관리를 위해 인증해 주세요’ TOTP 화면. 공용 PC에서 관리 인증을 했다고 신뢰 기기로 자동 등록하지 않는다. 관리 화면에서 파일 목록을 함께 노출하지 않는다.

### 8.2 기기 해제

대상 이름을 제목·본문에 반복해 실수를 줄인다. ‘iPad의 업로드 권한을 해제할까요?’ / ‘이 기기는 새 파일을 올릴 수 없고, 진행 중인 전송도 중단됩니다.’. 새 TOTP 입력. 현재 기기라면 ‘이 브라우저도 다시 인증해야 합니다.’를 추가한다.

서버 성공 응답 후 행은 ‘해제됨’으로 짧게 표시하거나 활성 목록에서 제거한다. 실패하면 행을 유지하고 dialog 내 오류 표시. 프런트엔드에서만 삭제하는 낙관 업데이트를 적용하지 않는다.

### 8.3 iPhone 단축어 연결

4단계: 이름 입력 → TOTP → 1회 token 표시 → 개인 단축어 설정·시험.

- 이름 기본 예: ‘내 iPhone 단축어’.
- 토큰은 생성 직후 한 번 표시, ‘복사’ 제공, textarea readOnly·전체 선택 가능.
- 안내: ‘이 토큰으로 파일을 올릴 수 있습니다. 다른 사람에게 공유하지 마세요.’
- ‘단축어를 공유하기 전에 토큰을 제거하세요.’
- 닫으면 재표시 불가, 잃어버렸다면 기존 기기 해제 후 재발급.
- clipboard를 자동으로 확실히 지울 수 있다고 약속하지 않는다.
- 설치용 템플릿과 개인 토큰을 분리한다. 실제 `.shortcut` 파일은 Apple 환경에서 제작·시험하는 별도 작업이다.

## 9. 마이크로카피 원칙

| 피할 문구 | 사용할 문구 |
|---|---|
| 영구 로그인 완료 | 이 기기를 신뢰하도록 등록했습니다 |
| 세션 종료로 업로드 중단 | 새 업로드 시간이 끝났습니다. 진행 중인 파일은 계속 전송됩니다 |
| 다운로드 완료 | 다운로드를 시작했습니다 |
| 안전하게 영구 삭제됨 | 보관 시간이 끝나 다운로드할 수 없습니다 |
| 업로드 100% = 완료 | 100% · 파일 확인 중 / 검증 후 업로드 완료 |
| 토큰 오류 | 이 파일의 전송 권한이 만료되었습니다 |
| 5GB 완벽 지원 | 단축어 지원 크기: 실기기 검증 결과로 확정 |

오류는 원인과 다음 행동을 한두 문장으로 쓴다. ‘문제가 발생했습니다’만 표시하지 않는다. 사용자가 고칠 수 없는 storage 오류에는 설정 변경을 요구하지 않는다.

## 10. 접근성 명세

- semantic header/nav/main, 페이지마다 h1 하나. 메뉴에 aria-current=page.
- 모든 input은 visible label. placeholder가 label을 대신하지 않음.
- code 입력 오류에 aria-invalid, 도움말 연결. Enter 제출·paste·키보드 숫자 지원.
- modal focus trap, autofocus 위치를 상황별 지정, Esc 허용, 닫은 뒤 트리거 focus 복귀.
- focus outline 2px 이상, 배경과 구분. 비활성 버튼은 opacity만이 아니라 disabled 의미도 적용.
- progressbar에 filename·현재값·최댓값, 변화 알림을 과도하게 읽지 않음.
- 200% 확대·320px 폭에서 핵심 작업 가능. 400%에서는 흐름·입력·버튼이 겹치지 않는지 검토.
- 경고·성공에 아이콘/텍스트 병행. 긴 파일명에 접근 가능한 전체 이름 제공.
- VoiceOver Safari에서 파일 선택·PIN·TOTP·dialog·progress·download를 수동 확인.
- prefers-reduced-motion 준수. 페이지 전환 애니메이션이나 진행 표시 pulse가 필수 정보가 되지 않음.
- 로그인 실패 후 입력 위치를 유지하고 메시지를 announce하되 모든 값을 자동 삭제하지 않음. TOTP는 새 코드 입력에 편하도록 선택 상태를 제공.

## 11. 화면 검토·개발 전달 기준

시안에는 다운로드 잠금/목록/빈 상태, 업로드 신뢰 기기/공용 PC/만료/인증/오프라인/완료, 기기 목록/해제·토큰 dialog를 포함한다. 예시 데이터와 가상 동작만 사용한다.

디자인 완료 기준은 스크린샷 한 장이 아니라 다음 항목의 일치다.

1. 상태표의 모든 상태에 문구·행동·버튼 활성 규칙이 있다.
2. API 오류 코드마다 UI 분기가 지정되어 있다.
3. 최소 390px 모바일·768px 태블릿·1440px 데스크톱 화면을 검토한다.
4. 업로드 중 페이지 이동·재인증·만료가 전송 엔진을 중단하지 않는 구조가 문서와 코드에 일치한다.
5. 시안에 있는 버튼 중 v1에 없는 기능을 실제 기능처럼 남겨두지 않는다.
6. 토큰·secret·signed URL이 화면 analytics·session replay로 수집되지 않도록 구현한다.

HTML 시안은 디자인 검토에 사용하는 산출물이며, 실제 인증·파일 업로드·보안·접근성 검증을 통과한 제품 구현이 아니다.
