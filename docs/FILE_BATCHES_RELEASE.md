# 업로드 묶음과 선택 작업

2026-10-04 · Asia/Seoul

운영 주소: https://drop.rmarkfcl.workers.dev

Worker 버전: `a22ca8f0-2cd9-4fdd-8f42-7ff194468a12`

## 동작

- PC에서 업로드 시작을 한 번 누른 파일들은 같은 묶음으로 표시한다. 같은 파일을 재시도하면 묶음 ID를 유지한다.
- 묶음은 펼치기/접기를 지원한다. 파일별·묶음별·불러온 목록 전체 선택을 지원하며, 한 번에 최대 100개를 선택할 수 있다.
- 선택 파일은 ZIP 한 개로 다운로드한다. UTF-8 파일명과 중복 파일명 접미사를 지원하며, R2 파일을 순서대로 읽어 ZIP64 STORE로 스트리밍한다. 파일 전체를 메모리에 모으지 않는다. CRC32는 `node:zlib`의 네이티브 구현을 사용한다.
- 선택 삭제는 대상 목록을 확인한 후 실행한다. 인증된 브라우저는 추가 TOTP 없이 삭제하고, 그 외 브라우저는 선택 ID 집합에 묶인 일회용 TOTP 승인으로 삭제한다. PIN 잠금 해제와 Origin/CSRF 검증은 모두 유지한다.
- 일부 저장소 삭제가 실패하면 해당 파일은 다운로드 목록에서 숨기고 기존 정리 작업이 재시도한다. 다른 선택 파일의 처리는 계속한다.
- 이전 파일과 `batchKey`가 없는 클라이언트의 새 파일은 개별 항목으로 남는다. 업로드 시각만으로 과거 파일을 임의로 묶지 않는다.

## iPhone 단축어 변경

기존 설치된 단축어는 자동으로 변경되지 않는다. `/shortcuts` 안내의 ‘한 번에 보낸 파일을 묶음으로 표시하기’를 따른다.

1. `각 항목 반복하기` **앞**에서 임의의 숫자 3개(각각 1~2147483647)를 만든다.
2. 텍스트 액션에서 `batch-숫자1-숫자2-숫자3`으로 연결하고 `묶음 ID` 변수로 저장한다.
3. 업로드 생성 POST의 JSON에 `batchKey`를 **텍스트** 유형으로 추가하고 `묶음 ID` 변수를 연결한다.
4. 반복문 안의 파일마다 같은 묶음 ID를 사용한다. 기존 파일별 `Idempotency-Key`는 그대로 유지한다.

`scripts/build-shortcut.py`의 서명 전 소스에도 같은 구조를 반영했다. 이 생성기는 설치 가능한 서명 파일을 제공하지 않는다. 변경한 묶음 버전은 iPhone 실기기에서 아직 검증하지 않았다.

## API와 migration

- `0004_file_batches.sql`: `files.batch_id`, 묶음 인덱스, 세션에 묶인 5분 ZIP 티켓 테이블. 운영 D1 적용 완료.
- `POST /api/uploads`, `POST /api/shortcut/uploads`: 선택적 `batchKey`(영문/숫자/하이픈/밑줄, 1~100자). 소유자와 함께 해시하여 다른 기기의 같은 키와 충돌하지 않는다.
- `GET /api/file-groups`: 25개 묶음 단위 페이지. 한 묶음을 페이지 사이에 나누지 않는다.
- `POST /api/files/archive`: `{ ids: string[] }` → `{ url, expiresAt }`. URL은 같은 다운로드 세션에서만 유효하며 만료·삭제 상태를 다시 확인한다.
- `POST /api/files/delete`: `{ ids: string[] }` → 파일별 `DELETED`, `PENDING`, `FAILED` 결과. TOTP가 필요하면 `intent: delete_files`, `targetIds`로 정확한 선택 집합에 대한 승인을 발급한다.

## 검증

- `npm run check`: 타입, 포맷, **68개 테스트**, production build 통과.
- 27개 파일의 같은 묶음, 기존 단축어 호환, ZIP의 선택 격리·세션 격리·만료, CSRF, 정확한 선택 집합에 대한 일회용 승인, 부분 삭제 실패를 테스트했다.
- 로컬·운영 API: 2 MiB + 1 바이트를 포함한 두 파일을 묶고 ZIP 다운로드. Python `zipfile`로 파일명·CRC32·SHA256 검증 통과.
- 실제 Chrome: 묶음 펼치기, 부분 선택의 중간 체크 상태, 전체 선택, ZIP 다운로드, 삭제 확인 창과 취소를 확인했다.
- 실제 운영 Chrome에서 두 파일을 한 번에 선택하고 업로드 완료 후 동일 `batchId`로 저장된 것을 확인했다.
- 실제 운영 Chrome에서 받은 ZIP도 선택한 두 파일의 바이트가 정확히 일치했다. 인증된 브라우저의 일괄 삭제 확인 창에는 추가 TOTP 입력이 없었다.
- 운영 API로 선택한 테스트 파일만 삭제하고, 선택하지 않은 파일이 남아 있는 것을 확인한 뒤 모든 테스트 파일 5개와 임시 검증 기기 권한을 정리했다. 기존 사용자 파일은 삭제하지 않았다.
- 390px 뷰포트에서 가로 넘침 없음. 수 GiB급 ZIP·iPhone 실기기 묶음 실행은 이번 검증 범위에 포함하지 않았다.

재검증 도구: `scripts/smoke-batches.mjs`. 자격 증명과 쿠키 상태 파일은 저장소 밖 비공개 경로에 저장한다.
